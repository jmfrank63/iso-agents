Reviewer: GPT-6.1-Sol via T3 delegated subagent (provider codex). All findings live-reproduced

## MAJOR

1. **WASM checker silently skips nested source files** — `checker.ts:36`: `include: ["*.ts"]`
   excludes files below `/app`'s immediate directory. `dir/guest.ts` with
   `const x: number = "bad"` returned ok:true. Bypasses the agent's typecheck gate.
   Fix: explicit `files` list of every submitted source + trusted globals; validate extensions.
2. **Guest filenames can overwrite checker config / hide behind trusted globals** —
   `checker.ts:54`, `host.ts:27`: guest `tsconfig.json` (e.g. `{noCheck:true}`) overwrote the
   seeded config → clean verdict; submitted `guest-globals.d.ts` replaced by trusted
   declarations, never checked. Fix: namespace separation, reject collisions, host-owned config.
3. **Held fs sync retains previous-request conflicts; escapes recycling** — `shim.ts:511/575`:
   new files written before obsolete removed (dir → dir/guest.ts = `mkdir /app/dir: not a
   directory`, repeated 500s, same instance gen); `prepared.start()` + result decode outside
   the catch. Fix: remove-before-write; one catch around sync+prep+run+decode dropping held state.
4. **Run deadline does not bound an iteration** — `loop.ts:127/228/293`: after the deadline,
   check+execute still proceed and can return `success` (5ms budget + 30ms provider → success
   ~31ms); provider retries get fresh timeouts. Fix: shared deadline/cancellation; re-check
   after each awaited stage; sandbox bounded by remaining budget.
5. **Guest controls test evidence** — `harness.ts:9`, `runtime.ts:220`: `__tests` is a writable
   guest global; guest cleared it and inserted `{name:"fabricated",passed:true}`; the loop
   trusted it. Fix: closure-private records + private host-side reader; protect harness fns.
6. **False-pass assertions** — `harness.ts:24/34`: `expect(NaN).toBeCloseTo(42)` passes
   (`NaN > tol` false); `expect(NaN).toEqual(null)` passes (identical JSON); undefined ≡ fn.
   Fix: validate operands; type-aware structural equality.
7. **Eviction of an active run prevents finalization** — `runs.ts:27/54`: 50 newer runs can
   evict a request's record while it awaits its provider; `finalize` no-ops; record stays
   `running`. Fix: finalize the caller-held reference; admission control for active runs.
8. **Unexpected failures leave permanently running records** — `index.ts:259`: checker/
   transpiler/sandbox exceptions bypass finalization; stored run stays `running` while the
   HTTP layer returns 500. Fix: catch around construction+loop → terminal internal-error
   finalization, partial transcript preserved.

## MINOR

9. **BigInt breaks HTTP serialization** — `runtime.ts:211`, `index.ts:72`: `1n` result → 500;
   `console.log(1n)` → guest-visible serialization error. Fix: one jsonSafe policy.
10. **Console cap exceeded** — `runtime.ts:116`: cap checked pre-dump; full entry retained
    (1MB retained despite 8KiB cap). Fix: per-entry bounded retention + truncation.
11. **Zero-test feedback hides real failures** — `loop.ts:307`: timeout/crash/gate-rejection
    with no tests reported only as "no test() calls found". Fix: status+error first.

## Reviewer's must-fix top 3
1. Checker gate: every submitted file checked; compiler-owned paths protected. (H1,H2)
2. Held-state synchronization request-independent; recycle on every failure path. (H3)
3. Run deadline enforced across stages and provider retries. (H4)

## Reviewer's closing assessment
"Intended paths are well demonstrated: all 64 unit tests, host type checking, and existing
live WASM/sandbox suites passed... the additional verified cases show that 'green' can mean
unchecked code or false assertion evidence, and completed requests can retain misleading
running states. These are correctness and boundary defects within the prototype's current
scope; they should be addressed before treating successful transcripts as reliable evidence."
