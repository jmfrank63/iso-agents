## Issues (blocking)

1. **runtime.ts does not compile under the pinned toolchain — `npm run check` fails (TS2571/TS18046).** `logBytes += args.reduce((n, a) => n + (...), 0)` — with `args: unknown[]`, typescript@6.0.3 infers the accumulator as `unknown` (`'n' is of type 'unknown'`), verified with the repo's own tsc under the repo's lib/strict settings. **Fix:** annotate the accumulator — `args.reduce((n: number, a) => ...)` (probe-verified exit 0) — or `args.reduce<number>(...)`. The plan's TS note only anticipates the `newVariant` generic; this line needs the same "decide by `npm run check`" treatment, but better fixed outright.

2. **Console injection silently drops the first guest argument — 3 live-harness cases fail.** The planned callback is `(thisHandle, ...argHandles) => { thisHandle.dispose(); ... }`, but `VmFunctionImplementation` is `(this: VmHandle, ...args: VmHandle[])` — a TypeScript **this-parameter** (type-level only), and the FFI calls `fn.apply(thisHandle, argHandles)` (verified in core `chunk-V2S4ZYJR.mjs`: `cToHostCallbacks.callFunction` builds `argHandles` from `argc` argv entries and applies). So `thisHandle` receives guest arg 0, is disposed, and never dumped: probe with the real pinned packages shows `console.log("answer", 42)` → `args: [42]`, `console.warn("heads up", {a:[1,2]})` → `args: [{a:[1,2]}]`. Live-harness console l0/l1/l2 assertions fail ⇒ `npm run test:live` fails. Note the RESEARCH skeleton (`(...argHandles) => ...`) was correct; the plan "improved" it with a wrong belief about the API. **Fix:** change the callback to `(...argHandles: QuickJSHandle[]) => {`, delete the `thisHandle.dispose();` line, and fix the comment claiming a "leading `this` handle" (guest `this` is scope-managed by the library). Probe-verified: all 27 behavior cases pass after this one-line fix.

3. **Planned unit spec fails against the planned harness source — `npm test` = 11 passing, not 12.** `expect(HARNESS_SOURCE.includes(".toEqual"))`, `".toBeTrue"`, `".toBeCloseTo"` are all **false** (probe-verified): the harness defines the chainable methods as object properties (`toEqual: function ...`) and never contains a `.method` call site. The `it("defines test(), chainable expect(), and assert()")` aborts at the first failing expect. **Fix:** assert the definitions, e.g. `HARNESS_SOURCE.includes("toEqual:")`, `includes("toBeTrue:")`, `includes("toBeCloseTo:")` (keep the `globalThis.test =` / `globalThis.assert =` checks, which do match).

4. **Count bug: `grep -c 'newVariant' src/sandbox/runtime.ts` returns 3, not 2.** Occurrences: import line, the comment `// ... this wasmfile+newVariant({wasmModule}) shape is the`, and the call. The criterion's parenthetical correctly rules out the `newQuickJSWASMModuleFromVariant` substring but misses the comment. **Fix:** change expected count to 3 (citing import + comment + call), or move the variant-explaining comment wording off the token.

5. **Count bug: `grep -c 'performance.now()' src/sandbox/runtime.ts` returns 7, not 6.** The six code sites are right, but the comment `// Wall-clock primary: performance.now() ADVANCES inside the interrupt` is the seventh. **Fix:** expect 7 (annotate the 7th as the comment), or reword the comment (e.g. "wall-clock primary: the handler clock advances during sync guest execution").

6. **Impossible criterion: `grep -rc 'singlefile' src/sandbox/` → 0 can never pass.** runtime.ts's own header comment says "The **singlefile** variant is DEAD on workerd…" — the supersession documentation the plan wants is what the grep forbids. Probe-verified count: 1. **Fix:** grep the import, not the word: `! grep -rn '@jitl/quickjs-singlefile' src/` → no match (dead variant not imported), and drop the `grep -c 'singlefile' src/sandbox/` → 0 lines from verify/acceptance and from 03-01's `<verification>` step 4.

7. **Count bug: `grep -c 'globalThis\.' src/sandbox/harness.ts` returns 7, not 6.** The header comment `// ... the runtime reads globalThis.__tests after the guest eval.` is the seventh occurrence; the annotated breakdown ("__tests assignment, test, two __tests.push, expect, assert") counts only code sites. **Fix:** expect 7 (6 code + 1 comment), or reword the comment (e.g. "the runtime reads the `__tests` global after the guest eval").

8. **Impossible criterion: `grep -c 'quickjs'` over identity/limits/gate/harness → 0 can never pass.** identity.ts contains `SANDBOX_IDENTITY = "quickjs-wasmfile-release-sync@0.32.0"` (probe-verified: 1 match). The `! grep -q 'quickjs' …` verify variant fails identically. The stated intent ("pure modules, no runtime import") needs the import pattern, not the brand string. **Fix:** `grep -c 'quickjs-emscripten-core' src/sandbox/identity.ts src/sandbox/limits.ts src/sandbox/gate.ts src/sandbox/harness.ts` → 0 (or `! grep -q 'from "quickjs' …`).

9. **Failing pattern: `grep -q 'declare module "\\*.wasm"' src/sandbox/wasm.d.ts` does not match.** After single-quoting, grep receives `declare module "\*.wasm"`; in BRE `\\*` parses as zero-or-more backslashes (quantified literal), and `"*.wasm"` never matches `"` + `\**` + `.` + `wasm"` (probe-verified MISS). Same BRE subtlety the `ASYNC_SOURCE_PATTERN` criterion gets right (`\\b` → literal backslash + `b`, verified MATCH). **Fix:** use a fixed-string grep: `grep -qF 'declare module "*.wasm"' src/sandbox/wasm.d.ts`.
