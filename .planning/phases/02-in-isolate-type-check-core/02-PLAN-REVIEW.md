## Issues (blocking)

1. **[02-01 T4 verify/acceptance; 02-02 T1+T2 — the `npm test` gates] In-workerd testing via @cloudflare/vitest-plugin crashes workerd once typescript.js is in the module graph.** Empirically reproduced 4× in scratch with the repo's exact toolchain: (a) fully-wired state — `test/healthz.spec.ts` alone hangs its first request (5008 ms timeout), worker exits with `WebSocket protocol error; statusCode = 1009; Message is too large` (kj/compat/http.c++), suite reports 1 failed of 6; (b) `minify: true` plugin option does not help; (c) a minimal worker whose only extra import is `typescript` (8.8 MB single module, no lib Text modules) crashes identically; (d) the Phase-1-size bundle (no typescript) passes 8/8 in the identical environment, isolating bundle size as the cause. The plugin has no transport/size knob (its option schema exposes only main/remoteBindings/verbose/additionalExports/miniflare/wrangler/experimental; Node talks to workerd over a WebSocket via `connectToMiniflareSocket`, and workerd rejects the oversized module message). The vitest-plugin transport with the big bundle was never probed by research — the spike ran only under `wrangler dev`, which is a different, working transport. Consequence: 02-01 T4's "npm test → 8 passing" and 02-02's "npm test → 18 passing" (its primary deliverable) cannot pass as planned, and neither can the in-workerd healthz-flip and route tests. **Required fix:** re-plan the verification strategy around transports that provably carry the bundle: keep `npm run check` + host-side executable unit checks for vfs/host/mapper (verified working in Node), and replace the vitest-plugin in-workerd typecheck/route/flip tests with the `wrangler dev` + curl harness (research-verified working with the full 11 MB bundle) — or first spike a vitest-plugin configuration that avoids shipping typescript as a single WS message and only re-gate on `npm test` if that spike is green. As written, both plans gate on a command that fails deterministically in this environment.
2. **[02-01 T3, src/typecheck/index.ts verbatim content] Compile error TS2459:** `import { GUEST_COMPILER_OPTIONS, GUEST_GLOBALS, makeHost } from "./host"` fails — host.ts imports GUEST_GLOBALS from ./vfs but never re-exports it (verified: `npx tsc --noEmit` → `error TS2459: Module '"./host"' declares 'GUEST_GLOBALS' locally, but it is not exported.`). `npm run check` cannot exit 0 as written. **Required fix:** one line — import `GUEST_GLOBALS` from `"./vfs"` in src/typecheck/index.ts (verified: with that single change the whole tree compiles clean and all other behavior holds), or re-export it from host.ts.
3. **[02-02 T1 exactness test + must_haves + acceptance criteria] Wrong expected column for TS2322.** The plan asserts `expect(d.column).toBe(19)` ("start of the 'not a number' literal"), but typescript 6.0.3 reports TS2322 for `const n: number = "…"` at the declared name, not the initializer. Verified by running the verbatim checker: diagnostic is `{"code":2322,"message":"Type 'string' is not assignable to type 'number'.","line":1,"column":7,"file":"/guest.ts","category":"Error"}`. The test, the must_haves line ("1-based `line:1`, `column:19`"), and the acceptance criterion all encode 19 and will fail at runtime. **Required fix:** expect column 7 (and correct the comment), or reshape the probe guest so the asserted offset is derived, not guessed. (Message, code, line, file, category expectations all verified correct.)
4. **[02-01 T1 verify/acceptance] Bundle gate unreachable at task-1 time.** The task runs `npm run bundle:check` and expects `ls dist-bundle | grep -c 'lib\.'` → 57, but at task-1 nothing imports src/typecheck/lib-imports.ts yet — esbuild only bundles the import graph from src/index.ts, so the 57 Text modules are not shipped. Verified empirically: Phase-1 index.ts + committed lib-imports.ts + rules config → Total Upload 4.35 KiB, **0** lib siblings. (The 57-sibling and >8192 KiB results only appear after task 4 wires src/index.ts → ./typecheck; verified: fully-wired dry-run = 57 siblings, 11,246.93 KiB.) **Required fix:** drop the bundle assertions from task 1 (keep script-output + grep gates there) and assert the 57-siblings/Total-Upload gates only after wiring, i.e., in task 4 or the plan-level verification where they currently also live.
5. **[02-01 T3 verify + acceptance criteria] Two wrong grep expected counts (the class of bug flagged for this phase):** (a) `grep -c 'getPreEmitDiagnostics' src/typecheck/index.ts` → planned expectation 2 ("assert + call"), actual **3** — the throw message string `"FATAL: typescript createProgram/getPreEmitDiagnostics missing…"` is a third matching line; (b) `grep -c 'performance.now()' src/typecheck/index.ts` → planned expectation 2 ("one per impl"), actual **4** — each impl has both the `t0` capture and the `ms` delta. Both verified by running the greps against the verbatim file. **Required fix:** correct the counts to 3 and 4, or tighten the patterns (e.g., `grep -c 'ts.getPreEmitDiagnostics(program)'` → 1).
6. **[02-02 T2 live-curl 405 check] The command greps the response body for a header.** `curl -s http://127.0.0.1:8787/typecheck | grep -o '"allow":"POST"'` — `allow: POST` is an HTTP response header (set by the 405 envelope helper), never part of the JSON body, so the grep always finds nothing. The acceptance criterion ("GET /typecheck still returns 405 with allow: POST") is right; the command implementing it is wrong. **Required fix:** e.g. `curl -s -o /dev/null -D - -X GET http://127.0.0.1:8787/typecheck | grep -i '^allow: POST'` (optionally with a `-w '%{http_code}'` status assert), or assert the body's `error.code === "method_not_allowed"`.
